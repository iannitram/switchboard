The CLI keeps only its wording and its exit codes. Owner ruling (2026-11-26): a face keeps its wording and its exit or reply shape, and every test that pins CLI wording stays green.

**How (settled):**

1. `CliWrites` keeps its five public fields exactly (`data`, `pipeline`, `dev_root`, `in_job_worktree`, `transport`) and `from_env`; the locked `cli_writes.rs` and `cli_drop.rs` build it field by field. It becomes the CLI's adapter: `impl switchboard_core::guarded::GuardedWrites for CliWrites`.
   - `merge`: `try_merge` as today, with `guarded::snapshots_for` and `guarded::resolve_repo` in place of the deleted functions. Every failure is `CoreError::Refused("merge {repo}#{pr}: {why}")`, the text of today. The `merge {repo}#{pr}: ` prefix is added here, in the adapter, not in `write_command`: the fake in `cli_rules.rs` returns its refusal whole.
   - `file`: `guarded::file`. `full_repo`: `guarded::full_repo`. `drop_requests`: `confirm::drop_requests_for(..).map(|dropped| dropped.lines)`. `confirm_restore_new`: settings from `config_dir()`, `guarded::confirm_restore_new`, then the lines of today (`{what}: done`, the lines, and `The request stays in Waiting on you.` when not cleared).
   - A folder that is not known is `CoreError::MissingPath(guarded::DATA_FOLDER)` or `CoreError::MissingPath(guarded::CONFIG_FOLDER)`, except inside `merge`, which keeps its text as above and so stays `CoreError::Refused` (step 5).
2. `real_merge` keeps its signature `fn(&str, u64) -> Result<(), String>` (MCP calls it from `main.rs`); it returns the text inside `CoreError::Refused`, or the error's `Display` for any other variant.
3. `run_with`, `write_command`, `drop_command` and `confirm_command` take `&dyn GuardedWrites`.
   - `write_command`: `guarded::resolve(action, false, writes)`, then `guarded::ask(&caller, &action, "the CLI", now, writes)`. `Asked::Merged` prints `merge {repo}#{pr}: done`. `Asked::Waiting { refusal, filed }`: a filing error prints one line `waiting: {error}` on stderr, then the command refuses with `refusal`, exit 1, filed or not. An `Err` refuses with its text, exit 1.
   - `drop_command`: `guarded::resolve(action, true, writes)`, then `writes.drop_requests`.
   - `confirm_command`: `writes.confirm_restore_new` as today.
   - `request_text` is deleted; `guarded::request_text` is the one copy.
4. One private function turns a `CoreError` into the CLI's text, used at every call above:
   - `Refused(why)` is `why`.
   - `MissingPath(guarded::DATA_FOLDER)` is `set SWITCHBOARD_DATA to the app data folder`; `MissingPath(guarded::CONFIG_FOLDER)` is `set SWITCHBOARD_CONFIG to the app config folder` (`CONFIG_ENV`).
   - Any other variant is its `Display`.
   - The prefixes of today stay: an error from `resolve` prints `switchboard: {command}: {text}` (`{command}` is `archive`, `restore` or `drop`; `delete` prints as `archive`), with `terminal_safe` applied to `{text}`; `Ok(None)` from `resolve` prints `switchboard: no such repo: {repo}`; a filing error prints `waiting: {text}`; a `drop_requests` or `confirm_restore_new` error prints `why` alone when it is `Refused`, else `drop: {text}` or `confirm: {text}`.
5. The Error code under `--json`: `not_found` for `Ok(None)` from `resolve`; `in_job_worktree` when the text passes `rules::is_job_worktree_refusal`; otherwise the code `ErrorBody::from(&CoreError)` gives. The exit code is 1 in every refusal case, as today.
   - Owner ruling (2026-11-26): a guarded write with the app data folder or the app config folder unset answers with the Error code `setting_missing`, not `refused`. That is what `ErrorBody::from` gives for `CoreError::MissingPath`. It holds for `archive` (and `delete`), `restore`, `drop` and `confirm restore --into`. The printed text and exit code 1 do not change; only the code under `--json` does.
   - `merge` is the one command left out: its adapter returns every failure as `CoreError::Refused` with the `merge {repo}#{pr}: ` text, so a merge with a folder unset still says `refused`. MCP's merge runs this same merge through `real_merge`, which hands back text only, and the two faces answer alike.
6. The read commands at lines 2240 and 2329 call `guarded::resolve_repo` and print the text of its error as they print the `String` today.
7. Tests:
   - `cli_rules.rs` and `cli_confirm.rs`: each `Fake` implements `GuardedWrites` (`merge`, `file`, `full_repo`; `cli_confirm.rs` also `confirm_restore_new`). In `cli_rules.rs` `full_repo` records the repo in `asked` and answers as `knows_repo` did, so `merge_never_asks_whether_the_repo_is_known` (line 252) keeps its meaning. `repo_known` is imported from `switchboard_core::guarded`. No expected output string in either file changes.
